# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`).

- `pnpm dev` — start the Vite dev server with HMR
- `pnpm build` — type-check all projects (`tsc -b`) then produce a production build (`vite build`)
- `pnpm lint` — run ESLint over the repo
- `pnpm preview` — serve the production build locally

The protocol core lives in **`@applesauce/concord`**, consumed from the immutable
`vendor/applesauce-concord-00ceaa38355d.tgz` artifact. SDK dependencies use stable
Applesauce v7; core is overridden to one 7.1.3 instance for shared registrations.
This Concord revision opts out of timeline batching for synchronous authority folds.
Protocol tests belong upstream. `pnpm test` runs app adapter/projection tests with Vitest.

**Updating Concord.** See `vendor/README.md` and `scripts/vendor-concord.mjs`.
Change the pinned revision deliberately, rebuild from an immutable git archive,
and update the artifact dependency/lockfile together. Preserve provenance/license
and run app tests, build and lint. Do not publish a snapshot as
part of an app change. Stable SDK patch versions are independent; preserve one
compatible core/relay/common/RxJS graph.

## Git workflow

**Commit after every feature or self-contained change.** Once a feature works (app tests, build and lint pass), make a focused git commit before moving on. Keep commits small and scoped to one feature so history stays reviewable; don't batch unrelated changes into one commit. Do not push unless asked.

## Architecture

This is a **React 19 + TypeScript + Vite** single-page app implementing a **Concord** client — Discord-style, end-to-end-encrypted communities over Nostr (spec in `refs/concord/`, a git submodule). Nostr I/O goes through the **applesauce** SDK. The entry point is `src/main.tsx`, which wraps `<App />` in `EventStoreProvider` + `AccountsProvider`.

### Layout

- `src/lib/bytes.ts` — hex/byte/base64url helpers. `src/lib/image.ts` — AES-GCM encrypt/decrypt of community/chat media blobs (the plaintext never touches a server). `src/lib/blossom.ts` — ciphertext upload over `blossom-client-sdk`.
- **Protocol core: the `@applesauce/concord` package** (vendored standalone artifact; see above). It provides CORD-01…06 crypto/stream/control/guestbook/permissions/editions/rekey/invite helpers, the CORD-07 voice-key derivations, casts/models, and the reactive client split into a thin **`ConcordClient`** manager (`{ signer, pubkey, pool, eventStore, uploader, autoUnlock }`; owns the Community/Invite lists + NIP-42 stream-key auth + a `Map<cid, ConcordCommunity>`) plus a per-community **`ConcordCommunity`** engine (messaging methods, and per-plane `channelStore(id)`). Two conventions the package is opinionated about, so prefer them in app code: **read** through the granular slice observables (`metadata$`/`channels$`/`roles$`/`grants$`/`members$`/`banlist$`/`dissolved$`), never the aggregate `state$` — it re-emits on *any* fold change, including a chat message in any channel (presence moves the member set), so a roles UI built on it re-renders on every message. **Write** through `community.admin` (metadata/channels/roles/members/invites/refound/dissolve) rather than the flat aliases it keeps for convenience; gate the UI on `can$(perm)` and, when acting *on a member*, on `canModerate$(member, perm)` — it carries both halves of the CORD-04 rule (hold the bit AND strictly outrank) plus the self-check, which hand-pairing `canDo` with a position does not. Import helpers/kinds from `@applesauce/concord/helpers`, types + client from `@applesauce/concord`. Importing the package side-effect-registers NIP-44 hidden content for 13302/13303 and the `User.concord*` casts.
- **App-side glue over the package** (things the package deliberately leaves to the client). The React UI is split into `src/views/` (full screens: `App.tsx`, `Login.tsx`, `settings.tsx`, `community-settings.tsx`), `src/components/` (reusable UI: `modals.tsx`, `MessageContent.tsx`, `User.tsx`, `EmojiPicker.tsx`, `QRCode.tsx`, `ThemeToggle.tsx`, plus the `voice/` call UI), `src/hooks/` (`use-community.ts`, `useDecryptedImage.ts`, `mentions.tsx`), `src/chat/` (message/thread fold logic), and the shared adapters/utils/contexts in `src/lib/`:
  - `src/chat/projection.ts` shares one ref-counted, task-batched projection per community/channel across messages, threads, unread counts and mentions. It reads `community.channelTimeline()` (current-ban filtering), retains originals/effects, and re-evaluates moderator deletes against current authority. `fold.ts` applies author edits, authorized deletes, reactions and NIP-22 comments; deleted effects are reversible when authority changes. `chat/actions.ts` builds nested NIP-22 replies rooted on kind-9 messages, not kind-11 forum threads.
  - `src/voice/` — the CORD-07 *runtime*. The package owns the key derivations (`voiceKeysFor`, `voiceSenderKey`, `VOICE_PRESENCE_KIND`) and delivers kind-23313 presence into the channel's plane store — its receive funnel decodes the ephemeral (21059) wrap and applies the CORD-03 binding check — but leaves the broker flow, presence fold, and join/leave lifecycle to the client. `presence.ts` — blind-broker token flow (`signAvGrant`/`fetchAvToken`, kind-27235 grant signed by `voice_key.sk`), presence fold + sole-claimant verification, §5 rendezvous. `engine.ts` — a per-community `VoiceEngine` providing `voiceKeys`/`getVoicePresence$`/`joinVoice`/`leaveVoice`; it reads presence off `community.channelStore(id).timeline([{kinds:[23313]}])` — **no subscription of its own** (an earlier version ran a duplicate 21059 sub because the package used to drop presence at ingest; don't reintroduce it) — and publishes via `community.sendEvent(..., {ephemeral})`, self-reflecting its own echo since the publish path skips the local echo for ephemeral wraps. `registry.ts` — one `VoiceEngine` per community + the `useVoiceEngine` hook + GC on community removal. **There is no voice-channel flag:** the package models no voice/text split, so every channel carries chat *and* can host a call. `voiceKeys` returning `null` means the room can't be *derived* (a private channel we hold no key for), not "not a voice channel".
  - `src/lib/concord-uploader.ts` — a `ConcordUploader` adapter (encrypt via `lib/image` → upload ciphertext via `lib/blossom` → return the package `MediaAttachment`), injected into `ConcordClient` so file attachments / community images work.
  - `src/lib/rumor-cache.ts` wires the Concord store factory to per-plane nostr-idb databases (`concord-rumors:<cid>:<planeKey>`). Retained kind-5 requests must hydrate through the verified database/memory/insert seam, never `store.add(delete)`, which destructively invokes the upstream delete manager. Hydration, write batches and removals are serialized; store/factory disposal flushes pending writes and closes handles; community deletion waits for closes before purging databases. Retain all non-ephemeral protocol and moderation evidence until a verified compaction boundary exists. Old caches are read in place; previously evicted originals require relay refetch. Plaintext rumor databases remain separate from the public-event cache.
  - `src/lib/concord-storage.ts` supplies account-scoped durable membership/key material storage, encrypting complete SDK values using an AES-GCM device key persisted as a non-extractable CryptoKey in IndexedDB. It migrates legacy localStorage mirrors/cursors/requested pending rotation records only after the encrypted write commits. SDK material writes must remain awaited, including deferred compensating writes after disposal; local commits and encrypted Community List relay publication are distinct. The provider enables automatic list publication and surfaces pending changes/retry. This device encryption does not protect against trusted same-origin scripts; rumor history remains plaintext in its own caches.
  - `src/hooks/use-community.ts` — `useCommunity(cid)` resolves the per-community `ConcordCommunity` from the manager (re-resolving on `communities$`).
  - **Invite links** (`InviteModal` in `components/modals.tsx`) go through `client.invites`, the package's manager for the user's private kind-13303 Invite List — so links minted on another device list here, and `revoke` tombstones the bundle *and* unregisters it from the community. A link can grant a subset of private channels (`CreateInviteOptions.channels`), and **grants none by default** — before `0.0.0-concord-20260714212055` every link carried every private channel key its creator held. Only offer channels the package reports as `accessible` (`channels$` now emits `ChannelView = ChannelMetadata & { accessible }`, and re-emits on a key grant alone): a private channel's *metadata* is public to every member (which is why the sidebar lists channels you can't read), but the bundle can only carry keys we actually hold, and the package throws on an id that isn't in our material. Those two sets differ — when testing a grant, assert on `material.channels` (or `hasChannelKey(material, id)`), never on what the sidebar renders. **`expiresAt`/`expires_at` are unix *seconds*** at every site, not milliseconds — the two are indistinguishable to `tsc`, and getting it wrong silently either mints links that never expire or renders every live link as expired.
- `src/nostr.ts` — the single `EventStore`, `RelayPool`, and `AccountManager` (persisted to localStorage; persistence gated behind `loadAccounts()` so the initial restore isn't clobbered). Imports `@applesauce/concord` for its register side effect and the seal/list kind constants used to build the NIP-46 signer permissions.
- `src/crypto-wasm.ts` — swaps pure-JS Schnorr verification for **nostr-wasm** (WASM libsecp256k1, ~4× faster) at startup: sets `eventStore.verifyEvent` and `setVerifyWrappedEventMethod(...)`. The wrapped-event method is the hot path — the Concord gift-wrap decoder (`getWrapSeal`) verifies a seal signature on *every* wrap decode across every plane, so it must go through applesauce-core's swappable `verifyWrappedEvent` hook (a small patch to `@applesauce/concord`'s `gift-wrap.ts` routes it there). Init is non-blocking; the first few ms fall back to JS. Event-id hashing stays on `@noble` sync sha256 (WebCrypto's async `subtle.digest` is slower for event-sized inputs and unusable in the sync hash path).
- `src/views/` + `src/components/` — React UI (Discord-style shell in `views/App.tsx`, `components/modals.tsx`, `views/Login.tsx`, `lib/context.tsx`). Styling is **Tailwind v4 + daisyUI v5** (the `@tailwindcss/vite` plugin; entry stylesheet `src/index.css` with `@plugin "daisyui" { themes: light --default, dark --prefersdark }`). There is **no custom CSS** — components use daisyUI components + Tailwind utilities inline with daisyUI semantic color tokens (`base-100/200/300`, `base-content`, `primary`, `error`, `success`), so both themes come for free. Theme selection lives in `src/lib/theme.ts` (`system|light|dark` persisted to the `accordion:theme` localStorage key → `data-theme` on `<html>`; a no-FOUC inline script in `index.html` applies it before first paint), surfaced by the account-bar `ThemeToggle` and the Appearance settings page.
  - `src/components/voice/` — the CORD-07 call UI (LiveKit). `CallProvider` holds the one active call and lazy-loads `VoiceRoom` (keeps the ~0.5MB `livekit-client` chunk out of boot); `VoiceRoom` builds the E2EE `Room` — LiveKit's built-in `e2ee-worker` + a custom `SenderKeyProvider extends BaseKeyProvider` (`sharedKey:false, keySize:256`, ratchet disabled) fed the externally-derived per-identity `voiceSenderKey` material (verified identities keyed, unverified given a random key so their frames never decode, §3/§7). Presence heartbeat is driven via the app-side `VoiceEngine.joinVoice`/`leaveVoice` (see `src/voice/`). `CallStage`/`CallBar` are the grid + controls; `brokers.ts` defaults `VITE_CONCORD_AV_SERVERS` to `https://armada.buzz` (the public Armada broker+SFU) so calls work out of the box. Mirrors armada's `PersistentVoiceRoom.tsx`. **The app is NOT wrapped in `<StrictMode>` (see `main.tsx`) — that is load-bearing for voice:** StrictMode's dev double-mount tears down + rebuilds the `Room`/`e2ee-worker` mid-handshake, leaving media E2EE half-initialized so every remote frame is silently dropped (mute/garbled audio). LiveKit's connecting-Room lifecycle can't survive a synchronous remount. **E2EE is enabled BEFORE connecting** (`setE2EEEnabled(true)` awaited, then the `LiveKitRoom` render is gated on `e2eeReady`): LiveKit turns the local frame cryptor on once, at `SignalConnected`, keyed off whether `encryptionType` is already GCM — enabling it after connect (racing the token fetch) loses that window and the cryptor never activates. `livekit-client` is pinned to `2.19.2` (armada's exact locked version; `keySize` in `KeyProviderOptions`, hence AES-256, only exists from 2.19.x). Audio publish config matches armada (`AudioPresets.musicHighQuality`, `red:true`, `dtx:true`); RED is auto-disabled by LiveKit whenever E2EE is on, so it never touches the frame crypto.
- **Testing.** Protocol round-trip/interop coverage belongs upstream in `@applesauce/concord`; do not run upstream dependency suites as an app check. Focused app adapter/projection tests run with `pnpm test`; there is no browser driver suite. To check a change by hand, `pnpm dev` and drive it in a browser; the app is a normal SPA with routes (`/c/:cid/:channelId`, `/c/:cid/settings/:page`, `/invite/:naddr`). Note if you script that: daisyUI labels are CSS-uppercased, so `innerText` matching must be case-insensitive.

### Nostr references

- `.mcp.json` enables two MCP servers: **applesauce** (`https://mcp.applesauce.build/mcp`) and **nostr** (`@nostrbook/mcp`). Use the **`applesauce` skill** and these servers rather than guessing at NIP/event/relay APIs.
- Relays must serve kind `1059` by author without enforcing NIP-59's `p`-tag guard (Concord reverses the wrap); `relay.damus.io` and `nos.lol` work.

### TypeScript project layout

Uses TypeScript project references (`tsconfig.json` → `tsconfig.app.json` + `tsconfig.node.json`). Bundler mode is strict: `verbatimModuleSyntax` is on, so use `import type` for type-only imports; `noUnusedLocals`/`noUnusedParameters` are enforced and will fail the build. `erasableSyntaxOnly` disallows runtime TS constructs (enums, parameter properties).
