# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **pnpm** (see `pnpm-lock.yaml`).

- `pnpm dev` — start the Vite dev server with HMR
- `pnpm build` — type-check all projects (`tsc -b`) then produce a production build (`vite build`)
- `pnpm lint` — run ESLint over the repo
- `pnpm preview` — serve the production build locally

The protocol core lives in **`@applesauce/concord`**, consumed from **JSR v0.1.0**
using pnpm's `jsr:` dependency protocol. SDK dependencies use stable Applesauce v7;
core is overridden to one 7.1.3 instance for shared registrations.
Protocol tests belong upstream. `pnpm test` runs app adapter/projection tests with Vitest.

**Updating Concord.** Use `pnpm add @applesauce/concord@jsr:<version> --save-exact`,
review the published APIs, and run app tests, build and lint. Preserve one compatible
core/relay/common/RxJS graph. Use the six public entrypoints, never internal paths.
`community.channels$` emits stable channel handles; `channelViews$` emits metadata.
Use `Databases`, `Drafts`, `KeyValue`, and `Media` for the storage interfaces and adapters.
Direct Invites are exposed by `client.directInvites$` and dismissed with `dismissDirectInvite`.

## Git workflow

Do not create or commit planning documents, investigation reports, handoffs, or other task write-ups in this application repository. Keep task plans and findings in the conversation instead.

**Commit after every feature or self-contained change.** Once a feature works (app tests, build and lint pass), make a focused git commit before moving on. Keep commits small and scoped to one feature so history stays reviewable; don't batch unrelated changes into one commit. Do not push unless asked.

Never end a task with your own significant changes left uncommitted. Commit your paths with `git commit --only -- <paths>`. If the user's uncommitted edits share a file you must commit (e.g. `package.json`/`pnpm-lock.yaml`, which cannot be split), include them in the same commit and say so in the message and your reply. Do not skip the commit or wait to ask.

## Architecture

This is a **React 19 + TypeScript + Vite** single-page app implementing a **Concord** client — Discord-style, end-to-end-encrypted communities over Nostr (spec in `refs/concord/`, a git submodule). Nostr I/O goes through the **applesauce** SDK. The entry point is `src/main.tsx`, which wraps `<App />` in `EventStoreProvider` + `AccountsProvider`.

### Layout

- **Services:** Prefer plain modules in `src/services/` exporting instances, observables, and methods for app service lifecycles. React views subscribe with `use$`; do not introduce React providers or contexts to own services.
- **Helpers:** `src/helpers/` holds reusable utility functions and adapter factories, without React hooks or active client lifecycles. Stateful storage/cache and preference management live in `src/services/`; React subscription hooks live in `src/hooks/`. The existing Concord provider lives in `src/components/ConcordProvider.tsx`, with its context consumer in `src/hooks/use-concord.ts`.
- **UI subscriptions:** Subscribe to client/conversation state with `use$` in the component that renders it. Avoid parent-built view models and duplicate message/preview caches. The DM list's small enumeration/delta bridge retains index metadata only; rows read their own SDK timelines.

- `src/helpers/bytes.ts` — hex/byte/base64url helpers. `src/helpers/image.ts` — AES-GCM encrypt/decrypt of community/chat media blobs (the plaintext never touches a server). `src/helpers/blossom.ts` — ciphertext upload over `blossom-client-sdk`.
- **Protocol core: the published `@applesauce/concord` package.** It owns CORD-01…08 protocol state, encryption, authority, sync, channel messages, pins, drafts and expiration; CORD-07 calls still need the app's media runtime. Create one `ConcordClient` per account and get communities through it. Read granular `metadata$`/`channelViews$`/`roles$`/`grants$`/`members$`/`banlist$`/`dissolved$` streams, rather than subscribing to aggregate `state$`. `channels$` provides stable `ConcordChannel` handles with `messages$`, `timeline$`, `pins$` and `draft()`. Write administration through `community.admin`; gate on `can$(perm)` and, for member actions, `canModerate$(member, perm)`. Import helpers from `/helpers` and client/types from the root. Root imports register Concord's hidden content and casts.
- **App-side glue over the package** (things the package deliberately leaves to the client). The React UI is split into `src/views/` (full screens: `App.tsx`, `Login.tsx`, `settings.tsx`, `community-settings.tsx`), `src/components/` (reusable UI: `modals.tsx`, `MessageContent.tsx`, `User.tsx`, `EmojiPicker.tsx`, `QRCode.tsx`, `ThemeToggle.tsx`, plus the `voice/` call UI), `src/hooks/` (`use-community.ts`, `useDecryptedImage.ts`, `mentions.tsx`), `src/chat/` (message/thread fold logic), and shared utilities in `src/helpers/` and client services in `src/services/`:
  - `src/chat/projection.ts` shares one ref-counted, task-batched presentation projection per channel across messages, threads, unread counts and mentions. It reads `channel.messages$` and visible reaction/delete inputs from `channel.timeline$`. Concord owns message edits, deletion authority, bans and expiry; `fold.ts` only adapts rows, groups reactions and organizes NIP-22 threads. `chat/actions.ts` uses `replyToThread`, with factory composition only for custom-emoji replies/edits unsupported by the convenience methods.
  - `src/hooks/use-channel-draft.ts` connects composers to SDK drafts, keeping typing synchronous while SDK writes serialize. Channel drafts retain text, attachments, titles and reply targets; thread drafts retain text. `ChannelPins` reads verified pins and writes replacements with banned-author entries preserved. `helpers/pins.ts` builds proofs from original cached seals using exported SDK helpers. `MessageExpiration` configures the community timer. `ConcordDiagnostics` displays background failures, including publishes that fail after local echo.
  - `src/voice/` — the CORD-07 *runtime*. The package owns the key derivations (`voiceKeysFor`, `voiceSenderKey`, `VOICE_PRESENCE_KIND`) and delivers kind-23313 presence into the channel's plane store — its receive funnel decodes the ephemeral (21059) wrap and applies the CORD-03 binding check — but leaves the broker flow, presence fold, and join/leave lifecycle to the client. `presence.ts` — blind-broker token flow (`signAvGrant`/`fetchAvToken`, kind-27235 grant signed by `voice_key.sk`), presence fold + sole-claimant verification, §5 rendezvous. `engine.ts` — a per-community `VoiceEngine` providing `voiceKeys`/`getVoicePresence$`/`joinVoice`/`leaveVoice`; it reads presence off `community.channelStore(id).timeline([{kinds:[23313]}])` — **no subscription of its own** (an earlier version ran a duplicate 21059 sub because the package used to drop presence at ingest; don't reintroduce it) — and publishes via `community.sendEvent(..., {ephemeral})`, self-reflecting its own echo since the publish path skips the local echo for ephemeral wraps. `registry.ts` — one `VoiceEngine` per community + the `useVoiceEngine` hook + GC on community removal. **There is no voice-channel flag:** the package models no voice/text split, so every channel carries chat *and* can host a call. `voiceKeys` returning `null` means the room can't be *derived* (a private channel we hold no key for), not "not a voice channel".
  - `src/helpers/concord-uploader.ts` — a `ConcordUploader` adapter (encrypt via `helpers/image` → upload ciphertext via `helpers/blossom` → return the package `MediaAttachment`), injected into `ConcordClient` so file attachments / community images work.
  - `ConcordProvider` supplies the package's account-scoped `Databases.createIndexedDBDatabaseFactory` and `Drafts.createIndexedDBDraftStore`. The SDK owns verified rumor persistence and community-history cleanup; dispose the client before closing these adapters. Plaintext rumor databases remain separate from the public-event cache. Expired messages are purged through `client.schedulePurge()`. Old snapshot-era caches are not imported.
  - `src/services/concord-storage.ts` supplies account-scoped durable membership/key material storage, encrypting complete SDK values using an AES-GCM device key persisted as a non-extractable CryptoKey in IndexedDB. It migrates legacy localStorage mirrors/cursors/requested pending rotation records only after the encrypted write commits. SDK material writes must remain awaited, including deferred compensating writes after disposal; local commits and encrypted Community List relay publication are distinct. The provider enables automatic list publication and surfaces pending changes/retry. This device encryption does not protect against trusted same-origin scripts; rumor history remains plaintext in its own caches.
  - `src/hooks/use-community.ts` — `useCommunity(cid)` resolves the per-community `ConcordCommunity` from the manager (re-resolving on `communities$`).
  - **User search.** `src/services/user-search.ts` keeps one `UserSearchIndex` (`helpers/user-search.ts`, fuse.js) per community, built from `members$` and kind-0 profiles and updated incrementally with coalesced flushes. Composer @-mentions and member pickers search it synchronously via `hooks/use-user-search.ts`, with no network access. Open Ranking (`hooks/use-open-ranking-search.ts`) is only the network fallback for people outside the community: direct invites in global scope, and DM search.
  - **Invite links** (`InviteModal`) use `client.invites` for cross-device listing and revocation. `CreateInviteOptions.channels` grants only explicitly selected private channels. Offer only `channelViews$` entries whose `accessible` flag is true: visible metadata does not imply held keys. Verify grants against `material.channels` or `hasChannelKey`. API `expiresAt`/`expires_at` fields use Unix seconds; raw invite bundles encode milliseconds, so read them with `getInviteBundleExpiry`.
- `src/nostr.ts` — the single `EventStore`, `RelayPool`, and `AccountManager` (persisted to localStorage; persistence gated behind `loadAccounts()` so the initial restore isn't clobbered). Imports `@applesauce/concord` for its register side effect and the seal/list kind constants used to build the NIP-46 signer permissions.
- `src/services/messages.ts` owns the account-scoped NIP-17 client lifecycle independently of React, exporting the active client/error observables and start/stop/restart methods. `src/messages/` supplies adapters over `WrappedMessagesClient` / `WrappedConversation` from `applesauce-extra/messages`; the SDK owns receiving, decryption, exact conversation matching, relay discovery and publication retries. Decrypted rumors persist in a plaintext `AsyncRumorStore` (Concord's IndexedDB rumor database under the `accordion:dm-rumors:v1` prefix), separate from the public-event cache; it is the source for DM views. Drafts and envelope/seal decryption caches reuse the device-encrypted storage adapter under `dm:<pubkey>`; conversation metadata uses the SDK IndexedDB index. `publication.ts` retains prepared SDK envelopes across route changes and partial failures within a client lifetime. `hooks/use-dm-feed.ts` infinite-scrolls a conversation by widening its rumor-store window and only calls the inbox-wide `messages/history.ts` coverage (one per client; NIP-17 history cannot be loaded per conversation) once the store has no older candidates; never add load-more/load-older buttons. `src/views/dm/` renders SDK state; do not reintroduce custom relay subscriptions, decrypt queues or wrapping/publish algorithms. The shared signed-event cache batches writes for five seconds, so offline reload checks must allow its flush.
- `src/crypto-wasm.ts` — swaps pure-JS Schnorr verification for **nostr-wasm** (WASM libsecp256k1, ~4× faster) at startup: sets `eventStore.verifyEvent` and `setVerifyWrappedEventMethod(...)`. The wrapped-event method is the hot path — the Concord gift-wrap decoder (`getWrapSeal`) verifies a seal signature on *every* wrap decode across every plane, so it must go through applesauce-core's swappable `verifyWrappedEvent` hook (a small patch to `@applesauce/concord`'s `gift-wrap.ts` routes it there). Init is non-blocking; the first few ms fall back to JS. Event-id hashing stays on `@noble` sync sha256 (WebCrypto's async `subtle.digest` is slower for event-sized inputs and unusable in the sync hash path).
- `src/views/` + `src/components/` — React UI (Discord-style shell in `views/App.tsx`, `components/modals.tsx`, `views/Login.tsx`, `components/ConcordProvider.tsx`). Styling is **Tailwind v4 + daisyUI v5** (the `@tailwindcss/vite` plugin; entry stylesheet `src/index.css` with `@plugin "daisyui" { themes: light --default, dark --prefersdark }`). There is **no custom CSS** — components use daisyUI components + Tailwind utilities inline with daisyUI semantic color tokens (`base-100/200/300`, `base-content`, `primary`, `error`, `success`), so both themes come for free. Theme selection lives in `src/services/theme.ts`, with its React subscription in `src/hooks/use-theme.ts` (appearance configuration persisted to `accordion:appearance`, migrating the legacy `accordion:theme` key → `data-theme` on `<html>`; a no-FOUC inline script in `index.html` applies it before first paint), surfaced by the account-bar `ThemeToggle` and the Appearance settings page.
  - `src/components/voice/` — the CORD-07 call UI (LiveKit). `CallProvider` holds the one active call and lazy-loads `VoiceRoom` (keeps the ~0.5MB `livekit-client` chunk out of boot); `VoiceRoom` builds the E2EE `Room` — LiveKit's built-in `e2ee-worker` + a custom `SenderKeyProvider extends BaseKeyProvider` (`sharedKey:false, keySize:256`, ratchet disabled) fed the externally-derived per-identity `voiceSenderKey` material (verified identities keyed, unverified given a random key so their frames never decode, §3/§7). Presence heartbeat is driven via the app-side `VoiceEngine.joinVoice`/`leaveVoice` (see `src/voice/`). `CallStage`/`CallBar` are the grid + controls; `brokers.ts` defaults `VITE_CONCORD_AV_SERVERS` to `https://armada.buzz` (the public Armada broker+SFU) so calls work out of the box. Mirrors armada's `PersistentVoiceRoom.tsx`. **The app is NOT wrapped in `<StrictMode>` (see `main.tsx`) — that is load-bearing for voice:** StrictMode's dev double-mount tears down + rebuilds the `Room`/`e2ee-worker` mid-handshake, leaving media E2EE half-initialized so every remote frame is silently dropped (mute/garbled audio). LiveKit's connecting-Room lifecycle can't survive a synchronous remount. **E2EE is enabled BEFORE connecting** (`setE2EEEnabled(true)` awaited, then the `LiveKitRoom` render is gated on `e2eeReady`): LiveKit turns the local frame cryptor on once, at `SignalConnected`, keyed off whether `encryptionType` is already GCM — enabling it after connect (racing the token fetch) loses that window and the cryptor never activates. `livekit-client` is pinned to `2.19.2` (armada's exact locked version; `keySize` in `KeyProviderOptions`, hence AES-256, only exists from 2.19.x). Audio publish config matches armada (`AudioPresets.musicHighQuality`, `red:true`, `dtx:true`); RED is auto-disabled by LiveKit whenever E2EE is on, so it never touches the frame crypto.
- **Testing.** Protocol round-trip/interop coverage belongs upstream in `@applesauce/concord`; do not run upstream dependency suites as an app check. Focused app adapter/projection tests run with `pnpm test`; there is no browser driver suite. To check a change by hand, `pnpm dev` and drive it in a browser; the app is a normal SPA with routes (`/c/:cid/:channelId`, `/c/:cid/settings/:page`, `/invite/:naddr`). Note if you script that: daisyUI labels are CSS-uppercased, so `innerText` matching must be case-insensitive.

### Nostr references

- `.mcp.json` enables two MCP servers: **applesauce** (`https://mcp.applesauce.build/mcp`) and **nostr** (`@nostrbook/mcp`). Use the **`applesauce` skill** and these servers rather than guessing at NIP/event/relay APIs.
- Relays must serve kind `1059` by author without enforcing NIP-59's `p`-tag guard (Concord reverses the wrap); `relay.damus.io` and `nos.lol` work.

### TypeScript project layout

Uses TypeScript project references (`tsconfig.json` → `tsconfig.app.json` + `tsconfig.node.json`). Bundler mode is strict: `verbatimModuleSyntax` is on, so use `import type` for type-only imports; `noUnusedLocals`/`noUnusedParameters` are enforced and will fail the build. `erasableSyntaxOnly` disallows runtime TS constructs (enums, parameter properties).
